# Raptor Sidebar

Collapsible container that sits beside main content (map, grid, page body) and holds filters, navigation, or auxiliary controls. When `collapsable`, it auto-renders a heading bar with a chevron anchor that toggles collapse on click.

## When to use
- A left/right panel that the user can collapse to reclaim space (filters, settings, a nav rail).
- An icons-only rail that hides text labels.
- A panel that auto-hides offscreen on narrow viewports.
- Several sidebars where opening one should auto-collapse the others (use `group`).

For tabbed content inside, compose `s.navTabs` (the Sidebar wires into an internal NavTabs to hide/show nav text on collapse). For a top app bar use `navbar.md`.

## Builder
Method `s.sidebar(options?)`, node `type: "sidebar"`, options interface `ViewDefinitions.ISidebar`. It is a root container — chain `.contentTemplates(s => ...)` to fill it. Children are returned to the renderer; on collapse, non-heading children get `d-none` and the width shrinks.

Key `ISidebar` fields:
- `sidebarWidth?: number` — expanded width in px (used as the restore width).
- `collapsable?: boolean` — render the heading chevron anchor and enable click-to-collapse. Without it, `collapseSidebar()` is a no-op.
- `collapsed?: boolean` — start collapsed.
- `heading?: string` — text shown in the heading bar next to the chevron.
- `collapsedIconsOnly?: boolean` — collapse to a narrow icons-only rail (~50px).
- `collapseOffscreen?: boolean` — attach a window-resize handler that hides the sidebar offscreen below ~375px and shows icons-only below ~767px.
- `respondToWindowResize?: boolean` — set `false` to opt out of the resize handler even when `collapseOffscreen` is set.
- `animate?: boolean` — animate collapse/expand.
- `chevronDirection?: SidebarChevronDirection` — `'left' | 'right'`; orients the double-chevron icon.
- `group?: string` — name shared across sidebars; expanding one collapses peers in the same group.

```ts
// View
const s = RSScriptor.create<MyVm>();
s.view("mySidebar", s =>
  s.sidebar({ heading: "Filters", sidebarWidth: 320, collapsable: true, chevronDirection: "left" })
    .contentTemplates(s => {
      s.div({}).contentTemplates(s => s.p({ text: "filter controls here" }));
    })
);
```

## Bindings & events
- `bindings?: Bindings.IRaptorUniversalBindings` — standard universal bindings (`css`, `attr`, `style`, `visible`, etc.).
- `events?: Events.IEvent_Sidebar[]` — events on the sidebar root (pointer / contextmenu / keyboard).
- `collapseAnchorEvents?: Events.IEvent_Anchor[]` — extra events on the auto-generated collapse anchor (the chevron). The built-in `pointerdown` collapse handler is added by the node itself; these are additive.

## ViewModel / instance API
Backing node class: `Sidebar` (extends `RaptorNode`). Reach the live instance from a VM via the view name you gave the sidebar:

```ts
const sb = this.raptorDom.nodeT<Sidebar>("mySidebar");
sb?.expand();              // expand only if currently collapsed
sb?.collapseSidebar();     // toggle (returns new collapsed state); respects collapsable
const isOpen = !sb?.collapsed;
```

Useful members:
- `collapseSidebar(silent = false): boolean` — toggle collapsed; returns new state. Resizes the dom and (unless `silent`) publishes the group event. No-op if `!collapsable`.
- `expand(): void` — expand if collapsed.
- `showMax()` / `hideMids()` / `hideMins()` — full / icons-only / offscreen states (the resize handler drives these).
- `collapseSidebarIconsOnly()`, `collapseSidebarOffscreen()`, `collapseSidebarOnscreen()`.
- `collapsed`, `collapsedIconsOnly`, `collapsedOffscreen` getters; `navTabs` getter (internal NavTabs ref, if present).

## Patterns
1. Filter panel beside a map: `s.sidebar({ heading: "Filters", collapsable: true, sidebarWidth: 320 })` with filter controls inside; the map/grid lives in the sibling region and reflows when the sidebar resizes (the node calls `raptorDom.resize()` and invalidates artboard caches on toggle).
2. Programmatic toggle from a button elsewhere: keep the view name stable, fetch with `nodeT<Sidebar>("mySidebar")`, call `collapseSidebar()` / `expand()`.
3. Mutually-exclusive panels: give two sidebars the same `group: "detail"`; expanding one auto-collapses the other (peers collapse silently, no event echo).

## Gotchas
- `collapsable: true` is required for the chevron and click-to-collapse to exist; otherwise `collapseSidebar()`/the anchor do nothing.
- The heading bar (`.sb-heading` list-group with the `.sb-collapse-anchor`) is generated by the renderer, not by your `contentTemplates`. Don't hand-build it.
- Collapse hides every direct child except the heading via `d-none` and forces the width small; structure content as children of the sidebar, not siblings.
- `collapseOffscreen` adds a window `resize` listener; pass `respondToWindowResize: false` to suppress it. The node cleans up listeners/ResizeObserver in `destroy()`.
- A `ResizeObserver` on the root triggers `raptorDom.resize()` when content height changes (e.g. an accordion inside expands) — expected, not a leak.
- There is a separate, unrelated `Sidebar` (an editor `CompositeControl`) in the type surface; the layout control here is the `Sidebar extends RaptorNode` class with `nodeModel: ISidebar`. `IMapLargeSidebar`/`MapLargeSidebar` is a hamburger-style variant.
